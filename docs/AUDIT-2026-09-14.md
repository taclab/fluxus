## 2. Failles et bugs corrigés

### Sécurité

| Sévérité | Constat | Correction |
|---|---|---|
| Critique | **Traversée de chemin** dans le repli SPA : `/..%2Fsecret` servait n'importe quel fichier du conteneur, sans authentification. | Résolution complète du chemin et vérification d'appartenance au dossier statique (`main.py`). Test de non-régression. |
| Élevée | **Anti-SSRF incomplet** : les redirections n'étaient pas revalidées (un flux public pouvait rediriger vers `postgres:5432`), et le service navigateur rendait n'importe quelle adresse, sous-ressources comprises. | `safe_get` revalide chaque saut avec résolution DNS asynchrone ; le navigateur refuse les hôtes privés et internes pour la page et pour chaque requête, et tourne sur un réseau Compose sans accès à Postgres. Tests. |
| Élevée | **Limiteur de connexion contournable** par un en-tête `X-Forwarded-For` forgé (force brute illimitée). | Plafond global toutes IP confondues (20 échecs / min) en plus du plafond par IP ; lecture de l'IP déléguée à uvicorn. Test. |
| Élevée | **Application Android bloquée par CORS** : la WebView a pour origine `https://localhost`, absente de la liste. | Origine ajoutée. |
| Élevée | Secret d'exemple accepté silencieusement (JWT forgeables, clés LLM déchiffrables). | Refus de démarrer si `FLUXUS_SECRET_KEY` est un placeholder ou fait moins de 32 caractères ; `POSTGRES_PASSWORD` et `DATABASE_URL` obligatoires dans Compose. |
| Moyenne | Sessions non révocables : le changement de mot de passe n'invalidait rien, `/refresh` acceptait un token d'appareil. | Version de mot de passe embarquée dans les JWT ; changement de mot de passe → nouveau jeton, autres sessions invalides, révocation optionnelle des appareils ; `/refresh` réservé aux sessions web. Test. |
| Moyenne | Aucun en-tête de sécurité HTTP. | CSP (`script-src 'self'`, iframes vidéo seules), `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`. Le script de thème inline est devenu un fichier. |
| Moyenne | Token accepté en query string (risque de fuite dans les journaux). | Supprimé. |
| Moyenne | Conteneurs en root ; Postgres publié sur toutes les interfaces ; pas de rotation des journaux ni de limites mémoire. | Utilisateurs non privilégiés (api, worker, browser), Postgres sur `127.0.0.1`, rotation 3 × 10 Mo, `mem_limit` et `pids_limit`, healthcheck du navigateur. |
| Moyenne | Upload OPML sans limite, parseur XML standard. | 5 Mo maximum, `defusedxml`. |
| Faible | Comparaison de domaines par sous-chaîne (`x.com` matchait `linux.com`), iframes filtrées de la même façon. | Comparaison par hôte exact ou sous-domaine. |
| Faible | Masquage des clés révélant 8 caractères. | 4 derniers seulement. |

### Robustesse backend

| Sévérité | Constat | Correction |
|---|---|---|
| Élevée | Serveur au goutte-à-goutte : le timeout httpx est par lecture, un flux hostile pouvait occuper un créneau du worker indéfiniment ; le corps était chargé entier avant troncature. | Délai global de 60 s et lecture en flux bornée (10 Mo flux, 5 Mo pages). |
| Élevée | Un `<author>` de plus de 300 caractères ou une URL de plus de 2 Ko faisait échouer la transaction ; le flux n'avançait plus et était re-planifié toutes les 30 s. | Troncatures dans le parseur ; toute erreur inattendue du job applique le recul exponentiel dans une transaction séparée. Test. |
| Moyenne | Collision de `dedupe_key` : le `rollback` annulait les jobs déjà ajoutés dans la même transaction (des flux perdus à chaque cycle dès qu'un flux était en attente). Reproduit. | Insertion sous SAVEPOINT. Test. |
| Moyenne | Horloge client en avance : `updated_at` projeté dans le futur figeait l'entrée. | Borne à +30 s et `updated_at = now`. Test. |
| Moyenne | Dates naïves dans `since` et les curseurs → 500. | Normalisation en UTC. Test. |
| Moyenne | Erreurs inattendues de l'extraction ou de l'enregistrement d'un résumé → 500 ou flux SSE coupé. | Capture complète, événement `error` explicite. |
| Moyenne | Travaux bloquants dans la boucle d'événements (DNS, feedparser, trafilatura). | Résolution asynchrone, parseurs en thread. |
| Faible | 304 sans rallongement de l'intervalle ; dédup intra-lot par hash incomplète ; index GIN absent des modèles ; `%` dans le mot de passe Postgres cassait Alembic ; migrations sans verrou. | Corrigés (verrou consultatif `pg_advisory_lock`). |

## 3. Ce qui reste ouvert

- **Sync en arrière-plan Android** quand l'application est fermée.
- **Règles de filtrage par flux**, **sauvegarde planifiée** de la base, **historique de lecture**.
- **Réglage de l'intervalle par flux** dans l'interface (l'API l'accepte déjà).
- **Rétention côté serveur** : la table `entries` croît sans limite (les clients purgent localement). À faire avec propagation des suppressions (`deleted_entry_ids` est réservé mais vide).
- **Limiteur de connexion en mémoire** : par processus, remis à zéro au redémarrage. Suffisant pour une instance ; à mettre en base si plusieurs répliques.
- **DNS rebinding** : la résolution de contrôle et la connexion httpx restent deux résolutions distinctes.
- Sur la machine de développement, `--forwarded-allow-ips` vaut `*` (réseau Compose privé) ; en production, renseigner `FORWARDED_ALLOW_IPS` avec l'IP du reverse proxy.
- Le service navigateur garde `--no-sandbox` (profil seccomp Docker) mais tourne désormais en utilisateur non privilégié.
